# CLAUDE.md — COT Dashboard

## What this project is

A static web dashboard that visualizes CFTC Commitment of Traders (COT) data for financial futures. It runs entirely in the browser — no server, no framework, no build step. Data is generated by a Python pipeline and stored as flat JSON files served from GitHub Pages.

---

## Repository layout

```
docs/           Static site root (deployed to GitHub Pages)
  index.html    Page structure — all IDs referenced by app.js are here
  app.js        All UI logic (~750 lines)
  style.css     Dark theme CSS (~440 lines)
  data/
    instruments.json    List of all 133 instruments with code, name, category
    *.json              Per-instrument time series (one file per CFTC code)

data/
  fin_futures.csv   Master CSV — every row ever published by CFTC (~44k rows)

scripts/
  fetch.py          Data pipeline (3 modes: historical / incremental / reprocess)
  requirements.txt  pandas, requests, yfinance

.github/workflows/
  fetch-data.yml    Cron job: every Friday 21:45 UTC
  deploy-pages.yml  Deploys docs/ to GitHub Pages on push to main
```

## Key constants and config (app.js)

### `FX_PAIRS`
Maps CFTC instrument name substrings to standard pair notation (e.g. `"EURO FX" → "EUR/USD"`). Used by `extractSymbol()` to display clean titles in the sidebar and instrument heading. **Order is critical — first match wins.** Cross-rate entries like `"EURO FX/BRITISH POUND" → "EUR/GBP"` must appear before the generic `"EURO FX" → "EUR/USD"` entry, otherwise all Euro cross instruments incorrectly show EUR/USD.

### `COLORS`
```js
const COLORS = {
  levMoney: { pos: "#34d399", neg: "#f87171" },
  dealer:   { pos: "#34d399", neg: "#f87171" },
  assetMgr: { pos: "#34d399", neg: "#f87171" },
  other:    { pos: "#fbbf24", neg: "#94a3b8" },
  oi:       "#818cf8",
  price:    "#e2e8f0",
};
```
All three main trader categories use the same green/red. The chart label disambiguates. Do not give each category a unique color — that was changed intentionally.

### `NAME_TO_TICKER` (fetch.py)
Maps CFTC instrument name substrings to Yahoo Finance tickers for price overlays. First match wins. When adding new tickers, put more specific substrings before shorter/broader ones to avoid false matches.

## Data flow

```
CFTC ZIP files (yearly)
  → fetch.py download + parse
  → data/fin_futures.csv  (master, never shrinks)
  → yfinance price fetch
  → docs/data/{code}.json (one per instrument)
  → docs/data/instruments.json (index)
  → GitHub Pages (static serve)
  → app.js (fetch at runtime, cache in Map)
```

Each `{code}.json` has this shape:
```json
{
  "code": "099741",
  "name": "EURO FX - CHICAGO MERCANTILE EXCHANGE",
  "units": "(EUR 125,000)",
  "rows": [
    {
      "d": "2006-06-13",
      "oi": 123456,
      "dl": 0, "ds": 0, "dsp": 0,
      "al": 0, "as_": 0, "asp": 0,
      "ll": 0, "ls": 0, "lsp": 0,
      "ol": 0, "os_": 0, "osp": 0,
      "pct_dl": 0.0, "pct_ds": 0.0,
      "pct_al": 0.0, "pct_as": 0.0,
      "pct_ll": 0.0, "pct_ls": 0.0,
      "p": 1.2345
    }
  ]
}
```
`p` (price) is optional — omitted when no Yahoo Finance match exists.

## Running the pipeline

```bash
# Install deps (once)
pip install -r scripts/requirements.txt

# Full historical load (first time only — slow, downloads everything from CFTC)
python scripts/fetch.py --mode historical

# Append new weekly rows (what GitHub Actions runs every Friday)
python scripts/fetch.py --mode incremental

# Rebuild all JSONs from existing CSV + re-fetch prices (no CFTC download)
# Use this after changing NAME_TO_TICKER or the JSON schema
python scripts/fetch.py --mode reprocess
```

## Serving locally

```bash
cd docs
python -m http.server 8000
# http://localhost:8000
```

No build step. Edit `app.js` or `style.css` and reload.

## UI architecture (app.js)

The app is a single-file vanilla JS SPA with hash-based routing (`#133741` → Bitcoin).

**Boot sequence:**
1. `DOMContentLoaded` → build category pills, attach controls
2. `loadInstruments()` → fetch `instruments.json`, render sidebar, then pre-fetch all instrument JSONs concurrently into `cache` (Map)
3. `handleHash()` → select initial instrument from URL hash

**Key functions:**

| Function | Purpose |
|---|---|
| `renderSidebar()` | Builds the instrument list; calls `updateCardData()` for cached instruments |
| `updateCardData(code)` | Updates a sidebar card's sparkline and Lev/Deal/AM flip values |
| `refreshView()` | Top-level render for the selected instrument; calls all sub-renders |
| `renderStatCards(latest, prev)` | Four summary tiles at the top |
| `renderBreakdown(latest)` | Position breakdown bars with flip label at the meeting point |
| `renderCharts(rows)` | Calls `renderBarChart` × 3 + `renderOIChart` |
| `renderBarChart(...)` | SVG bar chart with price overlay and crosshair |
| `renderOIChart(...)` | SVG area chart with price overlay and crosshair |
| `attachCrosshair(...)` | Adds interactive hover crosshair to any chart SVG |
| `fxPair(name)` | Returns pair notation for FX instruments, e.g. `"EUR/USD"` |
| `extractSymbol(name)` | Returns display symbol: FX pair if available, else abbreviated CFTC name |
| `inferCategory(name)` | Assigns Equity Index / Interest Rates / Currencies / Crypto / Other |

**State variables:** `instruments`, `cache`, `activeCode`, `activeCategory`, `activeWeeks`, `activeView`

## Flip value definition

"Flip" = net sentiment expressed as % of open interest:
- `levFlip = pct_ll − pct_ls` (Leveraged Money % long OI minus % short OI)
- `dealFlip = pct_dl − pct_ds`
- `amFlip = pct_al − pct_as`

Range: −100 to +100. Shown in sidebar cards and as the label at the long/short bar meeting point in the Position Breakdown.

The breakdown bar meeting-point flip is calculated from raw position counts:
`flip = (long − short) / (long + short) × 100 = 2 × pL − 100`

## Crosshair implementation

`attachCrosshair(container, values, dates, prices, fmtVal, colorFn, height, isBar)`

Called after each `renderBarChart` / `renderOIChart` sets `innerHTML`. Appends an SVG `<g>` (crosshair + tooltip) and a transparent overlay `<rect>` that captures mouse events. Mouse coordinates are converted to SVG space using `getBoundingClientRect()` + `W / rect.width` scale factor.

- Bar charts: snaps to `Math.floor(...)` — the bar under the cursor
- OI chart: snaps to `Math.round(...)` — nearest plotted point
- Tooltip flips to the left when within 14 + tooltip width pixels of the right edge

## Adding new instruments / price tickers

1. New CFTC instruments appear automatically when `fetch.py` is run — no code change needed
2. To add a price overlay for an existing instrument, add an entry to `NAME_TO_TICKER` in `fetch.py`, then run `python scripts/fetch.py --mode reprocess`
3. To add a currency pair label, add an entry to `FX_PAIRS` in `app.js` (substring match, first wins)

## GitHub Actions

- **fetch-data.yml** — runs `python scripts/fetch.py --mode incremental` every Friday at 21:45 UTC, commits changed files to `data/` and `docs/data/`
- **deploy-pages.yml** — deploys `docs/` to GitHub Pages on any push to `main` that touches `docs/**`

Manual trigger (Actions tab → workflow_dispatch) supports all three modes: `incremental`, `historical`, `reprocess`.
